crosswind, waves, near acquisition, far acquisition with radio on/off and
distractors on/off, and combined stress. Each condition has two map/seed
repeats. The full suite is required for a weighted overall score.

## Physical-start correction found during qualification

The first comparison was stopped before either learned-policy suite started.
Fourteen teacher flights had valid delivered conditions; the two wind setups
were correctly unscored. Wind moved the manually controlled boat during takeoff,
but the aircraft held an old absolute start coordinate. Actual ranges became
31.14 m and 28.78 m instead of 30 m, outside the 0.75 m tolerance.

Preparation now physically follows the prescribed relative start offset from
the boat's current position before the task clock starts. The task observation
and actor interfaces are unchanged. No mid-flight repositioning is introduced.
Physical setup-only checks cover the six wind/wave starts using real PX4, with
no timed policy execution. The corrected full comparison uses a new runtime
snapshot; old valid flights and exact harness sources are preserved as
qualification evidence, with no mixed-runtime total.

The driver now stops automatically on an invalid setup/infrastructure condition.
Windows preflight also detects missing/incompatible marker-kernel verification
source before model loading. The earlier no-radio decoy outcomes remain real
strategy failures under the shared mission reserve; the start correction does
not retune the teacher or learned policies.

## Windows and legacy-interface qualification

Deep model staging exposed Windows' ordinary path-length limit. Source bundles
now use native extended paths, without changing OS settings. Both selected
models were actually loaded from deliberately deep paths and ran 16 controller
and common-guard decisions for each radio mode. These are API probes, not
flight-performance measurements.

The common guard's absolute geometry import is bound to each staged policy's
own frozen camera helper. Older controllers publish an accepted registration as
`metric_valid`; a compatibility adapter exposes that same acceptance as
`metric_confirmed` when the newer field is absent. Explicit modern confirmation
values remain intact. This avoids false guard failures caused by interface
versions, without changing a neural weight, pose, threshold or controller.
The regression suite has 42 passing tests, including that compatibility.

One learned-policy qualification attempt hit a PX4 `dataman` startup timeout
before takeoff. Backend startup now permits at most three fresh-process attempts
before any physics or policy execution, with every attempt logged. It never
retries timed missions. An injected first-boot failure recovered through a real
second boot and valid wind takeoff at 30.09 m, with both boot attempts recorded
at simulation time zero. The batch requests system execution only while it is
running, preventing automatic idle sleep; display idle behavior is unaffected.

## Inference hardware qualification

The R15 CPU compatibility flight reached 61.48 simulated seconds in descent,
with its own learned perception/controller and no teacher commands. It was
stopped without a score after measuring about 142 ms per decision, slower than
the 40 ms control interval. Its partial trace remains in
`runs/policies_flight_qualified_20261024`.

This host provides an RTX 2060 with 6 GB VRAM and CUDA-enabled Torch. The final
matched learned comparison uses that same GPU for both checkpoints, recording
hardware and CUDA version and synchronizing latency measurements. CPU remains
an explicit supported option. This is an inference-device choice, not retraining
or controller retuning. The reference teacher does not use CUDA. Full-pipeline
radio-on/off contract probes are in `probes/cuda_pipeline_qualification/`.
The batch parent queries GPU metadata through a short-lived subprocess, avoiding
an unnecessary resident Torch/CUDA context alongside the flight worker.
