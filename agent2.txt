1. WHAT THE POLICY IS  (verified in code this session)
------------------------------------------------------
!! ONE FINAL VERSION (decided with the user 2026-11-19): student.onnx = main
   network + search head, NO pad finder, with the control code in
   tidewater-game/app/public/policy/reference/. It runs in the browser game
   and natively via benchmark.harness.tidewater_run. Benchmark: 79.9, 18/20,
   one run (benchmark/evidence/final/summary.json; full traces only local in
   benchmark/runs/tidewater_v1fix_20261119). Fails: waves-moderate-gravel and
   combined rock, both by hovering 0.5-0.9 m above the pad (pad_fix_too_old /
   too_high_for_blind_finish) until 240 s. Not investigated; the 8 Nov student
   landed waves-gravel in 53 s. The description below of the pad finder is
   history: it belongs to the 8 Nov benchmark student and R15.
   Fixes in the final version (19 Nov): blind-finish boat-speed limit 1.7 m/s
   (EARLY_COMMIT_MAX_BOAT_SPEED_MPS) and a one-turn near scan at up to 16 deg
   tilt after losing a close boat (tidewater_guidance.py, student_runtime.py).

Camera 640x360 on a pan/tilt gimbal, drone sensors, optional boat GPS radio.
Three networks see, none flies; control code computes the 6 commands
(3 velocities, yaw rate, pan rate, tilt rate) and PX4 flies them.
- Main network (R15 pose model, base/pose.pt): ~1.55 M params (MobileNetV3-Small
  encoder + 128-unit GRU). In: image, 32 numbers of own state incl. gimbal
  angles, memory. Out: 15 values (pad visible, pad position/velocity relative
  to drone, heading, deck normal, pad pixel, contact).
- Pad finder (R15 spatial_acquisition.pt): 45,092 params, image only. Out: one
  pad point + presence. While no fresh marker fit (>0.5 s), its point replaces
  the main network's pad point/visibility and the camera is aimed at it.
  Source: artifacts/approved_curriculum_20261020/candidate_exports/experimental_v39/
  package/base_r15/code/landing_training/radio_robust_20261015/runtime.py:74-85.
- Search head: 45,386 params (pad-finder design + 4-class evidence + 2-class
  identity), initialised from the pad finder's weights, trained with the other
  two frozen. 60 flights (48 train / 6 val / 6 test), 45 with decoys.
- Search without radio: climb to >= 7 m (student_runtime.MIN_SEARCH_HEIGHT_M),
  scan; pass 1 only target/similar boats, passes 2-3 also unknown boats
  (search_decision.py). The old separate 360 deg pre-check turn was removed
  2026-11-14. With radio: fly to the radio position, hand over after 4 frames of
  "target_boat" >= 0.5 that agree with the radio (student_radio.py).
- Near the deck the printed pad marking is fitted; descent pauses without a
  fresh fit (marker_policy.py:164).

(The browser export has no pad finder; that is now the intended final
   version, not a bug. student_runtime.py's pad-point override is dead code.)
