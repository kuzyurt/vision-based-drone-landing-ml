# ML speed and Intel UHD verification — 2026-10-15

## Hardware and scope

Windows lists an NVIDIA GeForce RTX 2060 and Intel(R) UHD Graphics. Native Dawn
D3D12 explicitly selected the Intel adapter for its checks: vendor `intel`,
device `intel-r-uhd-graphics`, driver `27.20.100.9664`. No browser was launched
and no OS GPU preferences or drivers were changed.

The full original 640×360 FP32 neural model, original CAD sensor and production
controller message path were checked on Intel. This is a focused component and
integration check, not a benchmark of the complete browser world/operator loop.
It does not establish sustained real-time gameplay on this Intel UHD.

## Retained changes and evidence

| Change | Focused measurement | Correctness check |
| --- | --- | --- |
| Intel NCHW instead of NHWC execution layout | Warm median neural call 44.631 → 27.881 ms; warm means 44.456 → 30.787 ms | Eight recurrent frames match checkpoint predictions/hidden state within 1e-4; all neural operations on GPU; FP32 unchanged |
| Exact camera transform prefix cache | 0.471407 → 0.048615 ms per transform, ~9.7× faster | Matrices bit-identical over 20 pan/tilt cases; calibration identity changes handled; returned arrays independently writable |
| Same cache through original camera-corridor solver | Warm controller replay 29.823/28.972 → 15.089/21.440 ms | Three original-vs-cached controller replays produce bit-identical actions, diagnostics and interventions |
| Reusable sensor GPU draw streams | Same-process Intel median command encoding: fixed views 15.758 → 12.129 ms; changed views 16.500 → 13.999 ms | Every original CAD RGB byte matches direct rendering in six alternating view pairs, including moved views |

Layout timings are eight-frame checks (first invocation excluded from warm
statistics), not long benchmarks; one NCHW sample took 48.074 ms. The native
shared-device test also checks texture input values and session close/reopen.
Weights, normalization, recurrence, dimensions and precision are unchanged.

The transform adapter retains the reference matrix multiplication and FP64
summation order. It caches immutable calibration steps and the latest exact
encoder-dependent prefix at each step. It retains one calibration and a bounded
number of matrices, without quantizing angles or accumulating flight history.
The original implementation remains callable for comparison. No least-squares
iteration limit, sample, threshold, action bound or landing gate was removed.

The draw cache records all existing resource bindings, offsets, draw counts and
ordering. It reuses a bundle only after an identical stream repeats; changed
streams replay direct commands. Geometry and material data still update each
frame, and resource/count/order changes invalidate the stream. At most eight
streams are retained, and sensor destruction clears them. A separate GPU test
checks updated transforms through reused bundles and bounded readback cleanup.

Additional marker ROI/segment precomputation trials were discarded because their
overall benefit was not consistent. The final marker WASM was rebuilt and is
byte-identical to `simulation/runtime/marker-kernel-before-igpu.wasm`.

## Actual complete focused policy path

The production shared neural/controller path ran five decisions using the
original CAD sensor and a timestamp-matched recorded observation. The first
decision includes cold registration. Four subsequent decisions measured:

| Adapter | Neural layout | Median complete decision |
| --- | --- | ---: |
| Intel UHD | NCHW | 67.457 ms |
| RTX 2060 | NHWC | 25.126 ms |

Both produced finite six-axis commands, phase `match`, and zero GPU errors.
Both also passed direct-versus-bundled original-CAD pixel comparisons. The native
test uses filesystem loading and Node timer/worker adapters; application policy,
camera, network and controller code are the production implementations.

The Intel result is approximately 15 decisions per wall-clock second, below the
25 Hz / 40 ms decision budget. Therefore Intel GPU execution is verified, but
the exact real-time target remains unmet in this focused workload. Full scenery
and operator rendering can add further work. Isolated neural throughput must
not be presented as full simulation throughput; current evidence does not
support promising 1× gameplay on this Intel UHD without further optimization.

## Browser selection and next verification

`?gpu=integrated` requests `powerPreference: 'low-power'`. The browser/OS may
choose a different adapter, so the flight HUD displays the actual adapter vendor.
Timing reports record both actual adapters, the requested preference, selected
neural layout and sensor bundle hit/miss/entry counts. Inference uses the same
device as rendering and rejects CPU fallback. Normal URLs retain the existing
high-performance adapter preference.

Use the existing 10-second timing recorder to measure full-scene browser
performance. No graphics, image size, physics, control frequency, trained model,
precision or physical landing confirmation criteria were reduced.
