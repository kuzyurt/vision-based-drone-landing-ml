# Handoff: repair the teacher as a coherent system

## The goal — read this before touching code

Build a **competent observable teacher and physically valid, purpose-correct scenarios** that can produce good training examples for finding the correct boat and reliably landing on it. The teacher must search when necessary, inspect genuinely ambiguous boats, prefer a recognizable target over irrelevant objects, approach safely, keep camera/vehicle tracking synchronized through descent, avoid unnecessary wobble/waiting, and recover appropriately from actual loss. Genuine learner-rescue examples must show actual difficulty followed by useful teacher control.

**The deliverable is sensible behaviour across the whole flight, not merely a working simulator, more episodes, a higher classifier score, or an eventual touchdown.** The user must be able to inspect the actual expert videos before bulk collection/training. Do not optimize a pipeline that multiplies a bad teacher's mistakes.

## Mistakes made previously — do not repeat them

- **Equating touchdown/technical integrity with good teaching.** They missed E01's obvious buoy pursuit and target neglect. Audit which object is selected throughout, why, and whether the whole behaviour makes sense.
- **Reactive isolated patches without a system model.** Fixing a callback or a camera helper did not establish correct priorities or that the failing active branch used the fix. Check integration and regressions across situations.
- **Assuming the intended scenario happened.** A named search may start with the target visible; a configured fault may never trigger; a prefix may never hand over; a supposed rescue may occur after contact. Require actual branch evidence.
- **Confusing learner footage, teacher-only demonstrations and assisted outcomes.** Show the expert the user asked to see. A teacher-prefix landing is not an independent learner success; a teacher-only rerun is not a rescue from the learner's actual difficult state.
- **Treating labels or confidence as truth.** `boat=true` admitted a buoy. Finite expert actions/`expert_label_valid=true` do not establish a competent teacher. A copied cross does not prove target design. Never feed observer truth into the actor to conceal these failures.
- **Making unsupported performance estimates and then waiting indefinitely.**47fps was not local full-flight throughput. Windows render-only tests measured1worker6.8fps and2workers11.07aggregate;4/8/12/16/24 were not run due RAM, not measured slower. Full E01 took about15minutes. CPU inference saved about0.8GB host RAM versus CUDA on the recorded-input probe; camera rendering stayed GPU. Profile the actual workload and useful alternatives before choosing guards/estimates. Do not kill other apps, lower safeguards blindly, duplicate jobs or restart failed flights without a specific justified change.
- **Quietly changing definitions, qualification gates or data provenance.** Same E-number across revisions does not mean same task. Preserve failed gates, quarantines, splits, originals and rejected evidence. Explain proposed requirements separately from observed/verified facts.
